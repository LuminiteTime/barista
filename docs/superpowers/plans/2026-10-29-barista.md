# barista Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Bind any Claude Code session to a Telegram chat/topic: inbound messages become prompts, every answer is mirrored back, artifacts and status reactions included.

**Architecture:** One Node 24 daemon under launchd owns the bot token and the only `getUpdates` loop; it exposes JSON-over-HTTP on a unix socket. A Claude Code mod in every session long-polls its inbox, submits prompts, mirrors answers, and exposes tools and `/tg`.

**Tech Stack:** TypeScript (Node 24 type stripping in dev, `tsc` emit for the package), zero runtime deps, ESLint + typescript-eslint, `node --test`, `claude plugin test`, Docusaurus for docs, GitHub Actions.

**Spec:** `docs/superpowers/specs/2026-10-29-telegram-bridge-design.md`

## Global Constraints

- Node ≥ 24; erasable TS syntax only (no enums, namespaces, parameter properties); relative imports end in `.ts`.
- Zero runtime npm dependencies. Dev deps only: `typescript`, `eslint`, `typescript-eslint`, `@types/node`.
- Lint: `max-lines: 200`, `max-lines-per-function: 40`, `complexity: 10`, `max-depth: 3`, `max-params: 4`.
- State dir `~/.barista/` (`0700`): `config.json` (`0600`), `state.json`, `files/`, `daemon.log`, `barista.sock` (`0600`). Override with `BARISTA_HOME` (tests).
- Only `from.id == ownerId` is obeyed; if `config.chats` is set, other chats are ignored entirely.
- Forum chats bind only by topic (`TOPIC_REQUIRED`); non-forum chats bind whole.
- Errors everywhere: `{ code, message, hint }`.
- Commits: Conventional Commits, owner as author, no co-author trailers.
- Package: `npm pack` tarball ships `dist/` (compiled JS; Node refuses type stripping under `node_modules`), `mod/`, `.claude-plugin/marketplace.json`.

## Review Focus

- Telegram 429 `retry_after` during bursts (albums, long splits): sender must wait and retry, not drop. → test in Task 4.
- Daemon restarted while sessions run: mods must reconnect silently and re-attach; status line shows the outage. → test in Task 7 (`attach` after restart restores binding from `state.json`).
- Markdown that `sendRichMessage` rejects (400 parse error): fall back to plain `sendMessage`, never lose the answer. → test in Task 6.
- Two sessions binding the same topic: second gets `TOPIC_TAKEN` while first is live; succeeds once first is offline (>60 s no poll). → test in Task 3.
- Files over Bot API limits (20 MB download / 50 MB upload): readable `FILE_TOO_BIG`, message still delivered with a note. → test in Task 5 / 6.
